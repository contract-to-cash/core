# 契約ライフサイクルデモ

トライアルから解約までの完全な契約ライフサイクルを示します。FIFO方式のクレジット適用を含みます。

## 実行結果

```
  Draft -> Trialing -> Active -> Suspended -> Active -> Cancelled

  1. 契約作成 (Draft)              ¥3,000/月
  2. トライアル開始 (14日間)        AutoConvert=true
  3. トライアル終了 -> Active       自動コンバージョン
  4. 初回請求書支払い              ¥3,300 (税込)
  5. 契約一時停止                  理由: 顧客の休暇
  6. 契約再開                     Activeに復帰
  7. クレジット発行                ¥1,000 (goodwill) + ¥500 (日割り)
  8. 2回目請求書 (クレジットFIFO)   合計 ¥3,300 - クレジット ¥1,500 = 請求額 ¥1,800
  9. 契約解約                     理由: 競合への乗り換え
```

## 主要コンセプト

| コンセプト | 説明 |
|-----------|------|
| **トライアル** | 自動コンバージョンとリマインダー設定付き14日間トライアル |
| **一時停止** | `SuspensionBillingSkip` -- 一時停止中は課金スキップ |
| **再開** | 契約がActiveに復帰し、次サイクルから課金再開 |
| **クレジット (FIFO)** | Goodwillクレジット(¥1,000)が先に消費され、次にプロレーションクレジット(¥500) |
| **解約** | イベント履歴が完全に保持される終端状態 |

## クレジット適用の詳細

```
請求書合計:  ¥3,300 (¥3,000 + 消費税10%)

クレジット1: ¥1,000 (goodwill)   -> 最初に適用 (createdAt順のFIFO)
クレジット2: ¥500  (日割り)      -> 次に適用

適用クレジット: ¥1,500
請求額:         ¥1,800
```

クレジットはFIFO順（古い順）で適用され、期限切れエントリはスキップされます。各適用は監査レコード（`BalanceApplication`）を作成します。

## 実行

```bash
go run ./examples/lifecycle-demo/
```
